# TODO: production-readiness bugs (2026-06-10 review)

Findings from a three-crate audit (helper / GUI / core). Severity in brackets.
Checked items in the "Verified sound" list at the bottom are NOT bugs; they were
investigated and cleared, kept so they are not re-reported.

## A. Critical: root data loss (fix before shipping)

- [ ] A1 [critical] **Helper does not validate `device_path`** (`crates/helper/src/main.rs:119-215`, every job module). `run()` passes the attacker-controllable JSON `device_path` straight to `dd`/`zero_device`/`partition::write_*`/`mkfs` with no check that it is (a) a block device, (b) removable, (c) not the running system disk. `O_EXCL` is a no-op on regular files, so a buggy/malicious unprivileged GUI can make root erase `/dev/sda` or overwrite any regular file. Defeats the privilege-split threat model. Fix: stat the path, require `S_ISBLK`, resolve via `/sys/block/<name>` and reject non-removable / whole-system disks, failing closed.
- [ ] A2 [critical] **`unmount_all` will lazily detach `/`** (`crates/helper/src/blockdev.rs:248-289`). Mount matching accepts any `/proc/mounts` source that is `device` followed by digits/`p`; for `device_path=/dev/sda` with `/` on `/dev/sda2`, `umount("/")` returns EBUSY and the `umount2("/", MNT_DETACH)` fallback (line 281) lazily detaches the live root fs as root, before any device check fires. With A1, a one-line JSON system-destroyer. Fix: gate A1 first, and refuse to unmount `/`, `/usr`, `/boot`, or any mountpoint outside `/run/media`, `/media`, `/mnt`.

## B. Major: user-facing failures a release will hit

- [ ] B1 [major] **Persistence patcher uses unbounded substring replace** (`crates/helper/src/persistence.rs:281`). `content.replace(marker, replacement)` with anchor `/casper/vmlinuz` matches inside `/casper/vmlinuz.efi`, producing `/casper/vmlinuz persistent.efi` and breaking the kernel path: the copy "succeeds" but the stick will not boot. Same hazard for any anchor that is a prefix of a longer token. Fix: anchor on a token boundary (match only when followed by whitespace/end), or operate on whitespace-split args.
- [ ] B2 [major] **UDF extent reader: unbounded zero-fill OOM** (`crates/core/src/udf.rs:388-430`, via `read_file_data:280` and `read_dir:224`). `Vec::with_capacity(...min(64MiB))` is only a hint; `read_extents` drives `remaining` from the attacker-controlled `information_length`, and sparse descriptors (`kind==1|2`) do `out.resize(out.len()+take, 0)` with no disk read. A crafted dir or `/EFI/BOOT/*.efi` entry forces hundreds of GiB of zero-fill, OOM-crashing the GUI on the first `udf.list`/`read_file` during analysis. The UDF EFI-scan path has no `MAX_EFI_SCAN_BYTES` cap (unlike ISO9660). Fix: track cumulative `out.len()` and bail past a ceiling (64 MiB files / 16 MiB dirs); clamp `remaining` before the loop.
- [ ] B3 [major] **Cancel during pre-flight is silently dropped and disables the button** (`crates/gui/src/bridge/jobs.rs:243-288,373`, `runner.rs:236`, `main.qml:61,1020`). `start()` re-enumerates, runs `udisksctl unmount` (seconds), downloads UEFI:NTFS/FreeDOS, then waits for polkit auth, all before `stdin_slot` is populated. `cancel()` writes "cancel" only if stdin is `Some`, with no pending-cancel flag, yet QML latches `cancelling=true` and disables the button until `busy` flips at job end. A cancel in that multi-second/minute window is lost with no further way to abort. Fix: `cancel_requested: AtomicBool` in `JobHandle`, checked by `run_job` before/after spawning the helper.
- [ ] B4 [major] **Decompress / VHD-unwrap / analyze cannot be cancelled, but the UI shows Cancel** (`crates/gui/src/bridge/iso.rs:40-85`, `decompress.rs:167-310`). `set_iso` on a compressed image sets `busy=true` with no `JobHandle` and no abort flag; the decompress loop never checks for cancellation. A 10 GB `.iso.zst` picked by mistake cannot be aborted. Fix: thread an `Arc<AtomicBool>` into `decompress_to_cache` (poll in `copy_with_progress`) and park it in a `JobHandle`.
- [ ] B5 [major] **Windows download truncates/deletes a same-named existing ISO** (`crates/gui/src/windisco.rs:218-219,261-266`). `File::create(downloads/<canonical-name>)` truncates an existing good ISO immediately, and the error/cancel path then `remove_file`s it. One mistaken click + cancel destroys the user's prior download. Fix: stream to a unique `.part` temp file, rename into place only on success, uniquify the final name if it exists.
- [ ] B6 [major] **No HTTP timeouts; a stalled connection wedges the app in `busy` forever** (`crates/gui/src/windisco.rs:78-94,206-209`, `resources.rs:177-201,355-423`). `ureq` 3 defaults to no timeout (rgadguard.rs:56 already sets 8s, so the codebase knows). `win_fetch_*` spawn workers with no `JobHandle`, so cancel is a no-op; `resources::ensure*` inside `run_job` is stuck with `stdin_slot` empty too. Fix: set global/per-call timeouts on every ureq agent/request in `windisco.rs` and `resources.rs`.
- [ ] B7 [major] **`write_mbr` lacks the >2 TiB / non-zero guard the other MBR paths have** (`crates/helper/src/partition.rs:188-210`). Hybrid/UEFI:NTFS/persistence MBR builders all `u32::try_from(...).context("exceeds the MBR 2 TiB sector limit")`; the plain single-partition path does not, so a >2 TiB MBR target is silently sized wrong, and `start+sectors-1` can underflow on a sub-1 MiB target. Fix: mirror the `try_from` guard and a `sectors>0` check.

## C. Minor: hardening / polish

- [ ] C1 [minor] **Stale SMART warning shown against the wrong device** (`crates/gui/src/bridge/devices.rs:92-108`). `probe_smart` has no generation/path guard: a slow probe for device A lands after device B is selected and is shown for B; `refresh_devices`/eject remap `selected_device` without clearing `smart_warning`. Fix: capture the device path with the worker, compare against `selected_info()` in the queued closure; clear `smart_warning` on remap.
- [ ] C2 [minor] **Destructive check/backup skip the safety re-scan `start()` does** (`crates/gui/src/bridge/jobs.rs:294-368` vs `:243-259`). `start_check` (writes patterns) and `start_backup` use the cached path and skip the `unmount_device_partitions` pre-flight and device-identity re-verify. Fix: route both through the same pre-flight worker as `start()`.
- [ ] C3 [minor] **Unbounded decompression output; `.Z` decodes fully into RAM** (`crates/gui/src/decompress.rs:414-439,546-573`). No free-space check or output ceiling, so a zstd/xz bomb fills `$HOME`; `DotZAdapter` reads the whole payload and decodes the full output into memory (OOM on a crafted few-MB `.Z`). Fix: `statvfs` free-space check + output ceiling; stream `.Z` via weezl's streaming API.
- [ ] C4 [minor] **Stale inspect text race** (`crates/gui/src/bridge/devices.rs:226-241`). Two rapid `request_inspect` calls race; last finisher wins regardless of current selection. Fix: same path-compare guard as C1.
- [ ] C5 [minor] **Panic slicing a non-ASCII device serial** (`crates/core/src/device.rs:65`). `&s[..14]` slices at byte index 14; a serial with a multibyte char straddling byte 14 panics and takes down the device picker. Fix: `s.chars().take(14).collect::<String>()`.
- [ ] C6 [minor] **`format_size` rounds across a unit boundary** (`crates/core/src/device.rs:74-87`). `999_950..=999_999` bytes renders `1000.0 KB` instead of `1.0 MB`. Cosmetic. Fix: re-check `value >= 999.95` after dividing and bump the unit.
- [ ] C7 [minor] **Loose substring distro needles** (`crates/core/src/iso_report.rs:202-248`). `("tails", Tails)` matches "...details...", `("rocky", Rocky)` is substring-only. Low impact (short labels). Fix: anchor the loosest needles with a delimiter, like the `*linux`/`*-`/`*_` forms used elsewhere.
- [ ] C8 [minor] **Argument injection via leading-dash paths into shelled-out tools** (`crates/helper/src/fsutil.rs` mkfs.*, `freedos.rs:144-152` mcopy/mformat). Labels are safely after their flags, but device/file positionals built from JSON beginning with `-` are parsed as options. Limited impact (DoS/odd behaviour), compounds A1. Fix: insert `--` before positional device/file args where supported; canonicalize/validate.
- [ ] C9 [minor] **Job delivery aborts if the GUI closes stdin after sending the job** (`crates/helper/src/main.rs:84-100`). `stdin_watcher` treats EOF as cancel, but a GUI that writes the job then closes its write end sets `ABORT` before work begins. Latent (the GUI currently holds stdin open). Fix: treat EOF as abort only after work has started, or document/enforce the held-open contract.
- [ ] C10 [minor] **Large-log UI degradation** (`crates/gui/qml/main.qml` log TextArea). "Log every copied file" on a huge job appends 10^4+ lines to a RichText `TextArea`, re-laying-out a growing document each append. Not a leak (Rust strings reset per job). Fix: cap the rendered line count in the QML view.

## Verified sound (investigated, NOT bugs)

- `O_EXCL` whole-disk open closes the unmount→open remount race for real block devices.
- Every success path fsyncs/syncs before "Done"; temp mounts/loop devices use RAII guards cleaned on every error path; backup/ventoy seed remove partial output on abort.
- GPT path is fully u64-LBA clean past 2 TiB; hybrid MBR explicitly rejects >2 TiB.
- 4Kn sector size queried and threaded through partitioning (tested).
- BLAKE3 verify (hash-source-during-copy, evict cache, re-read destination) is sound.
- Hash workers / adguard badge / hash progress correctly guarded by `hash_generation`.
- Zip handling has no zip-slip; interrupted decompress/VHD caches use atomic persist keyed by canonical-path/size/mtime.
- `start()` device-swap TOCTOU handled by re-enumeration + identity compare.
- `file://` percent-decoding correct incl. malformed escapes (tested).
- No `unwrap`/`expect`/`panic!` on runtime data in non-test GUI code; mutex locks recover poison.
- revocation/DBX/SBAT parsing bounds-checked with `.get`, no length-driven allocation, loops terminate.
- udf `read_dir` has forward-progress + bounds guards, no recursion/infinite-loop reachable.
- serde contracts: every post-v1 field carries `#[serde(default)]`; no GUI/helper skew break.
